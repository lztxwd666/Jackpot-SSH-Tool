# 项目理念

> 构建一个现代化、轻量级、高性能的 SSH 客户端，专注于 SSH 工作流本身。

---

# 愿景

本项目旨在构建一个现代化的桌面 SSH 客户端。

目标**不是**成为另一个"一体化远程管理套件"。

相反，目标是以卓越的性能、直观的交互和清晰的架构，提供最佳的 SSH 使用体验。

本项目优先考虑可维护性、可扩展性和长期稳定性，而非功能数量。

---

# 核心价值观

## 1. SSH 优先

SSH 是本项目的核心。

一切都围绕 SSH 工作流展开。

受支持的功能应仅在其能直接改善 SSH 使用体验的情况下存在。

示例包括：

- SSH 终端
- SFTP
- HostKey 管理
- 凭据管理
- 会话管理
- 端口转发（未来）
- SSH Config 兼容

本项目有意**不**尝试成为：

- FTP 客户端
- RDP 客户端
- VNC 客户端
- 串口工具
- 数据库客户端
- Docker 管理器
- 文件编辑器
- 远程桌面套件

如果一个功能不能改善 SSH 工作流，它就不属于本项目。

---

## 2. 轻量级

轻量级**不**意味着功能更少。

轻量级意味着：

- 快速启动
- 低内存占用
- 低 CPU 占用
- 最少的运行时依赖
- 尽可能使用原生平台能力
- 无不必要的抽象
- 无重复功能

性能被视为一等特性。

每引入一个依赖，都必须有明确的理由。

---

## 3. 核心优先

Core 是本项目最重要的部分。

图形界面只是可能的前端之一。

Core 绝对不能依赖于：

- React
- Tauri
- xterm.js
- 任何 GUI 框架

Core 应当可被以下场景复用：

- 桌面 GUI
- CLI
- VSCode 扩展
- JetBrains 插件
- 未来的应用程序

---

## 4. 职责分离

业务逻辑与用户界面完全分离。

Core 负责：

- SSH
- SFTP
- 会话
- 数据库
- 凭据
- HostKey
- 配置
- 状态管理

UI 仅负责：

- 渲染
- 用户交互
- 视觉反馈

UI 绝对不得实现业务逻辑。

Core 绝对不得知晓 UI 的存在。

二者之间的通信仅通过以下方式进行：

- IPC
- CoreEvent

---

## 5. 事件驱动

Core 通过事件暴露状态变化。

UI 响应事件。

Core 从不直接操作界面。

每一个重要操作都应表示为一个状态转换。

示例：

- 正在连接
- 已连接
- 认证已开始
- 认证成功
- 上传进度
- 下载完成
- HostKey 已变更

这种架构使系统更易于扩展、调试和测试。

---

## 6. 原生平台集成

应尽可能优先使用原生平台能力。

示例：

密码：

- Windows 凭据管理器
- macOS 钥匙串
- Linux Secret Service

HostKey：

与 OpenSSH 兼容。

SSH Config：

与 OpenSSH 兼容。

本项目应集成到现有 SSH 生态系统中，而非取代它们。

---

## 7. 稳定性优于功能

一个功能只有在满足以下条件时才算完成：

- 稳定
- 可维护
- 可预测

增加功能从来不是目标。

改善现有工作流才是。

---

## 8. 开放标准优先

当已有既定标准存在时，应采纳而非另起炉灶。

示例：

- OpenSSH Config
- OpenSSH Known Hosts
- SSH Agent Protocol
- 标准 SFTP 协议
- 标准终端转义序列

本项目应自然地融入现有的开发环境。

除非绝对必要，避免发明自定义格式或专有工作流。

---

# 开发原则

每个模块都应满足：

- 单一职责原则
- 明确的所有权
- 最小化公共 API
- 易于测试
- 低耦合
- 高内聚

---

# 非目标

以下内容有意地不在本项目范围内：

- 远程桌面
- VNC
- Telnet
- FTP
- 数据库客户端
- Docker 管理
- Kubernetes 仪表盘
- 文本编辑器
- IDE 功能

这些属于专用工具的范畴。

---

# 长期目标

本项目应成为：

- 一个可复用的 SSH Core 库
- 一个现代化的桌面 SSH 客户端
- 现有商业 SSH 客户端的高性能替代品
- 一个清晰、可维护的开源项目

架构应在持续开发多年后仍然清晰易懂。

可维护性比快速功能扩展更为重要。
