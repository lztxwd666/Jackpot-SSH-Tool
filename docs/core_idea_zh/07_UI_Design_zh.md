# UI 设计

> 定义图形界面的设计理念与交互原则。

UI 仅负责呈现与用户交互。

业务逻辑完全属于 Core。

---

# 设计理念

UI 应当是：

- 快速的
- 响应式的
- 可预测的
- 极简的
- 现代化的
- 键盘友好的

界面的存在是为了改善 SSH 工作流。

视觉复杂度绝不应替代可用性。

---

# 核心原则

## 原则 1

UI 绝不持有业务逻辑。

UI 可以：

- 显示
- 动画
- 过滤
- 排序
- 搜索
- 高亮

UI 绝不得：

- 连接 SSH
- 验证 HostKey
- 保存数据库
- 管理凭据

---

## 原则 2

UI 对事件做出响应。

界面是 Core 状态的反映。

每个可见的变化都应由 CoreEvent 驱动。

UI 绝不应猜测运行时状态。

---

## 原则 3

响应性是强制要求。

界面在以下操作期间必须保持响应：

- 连接中
- 上传中
- 下载中
- 目录刷新
- 认证中
- 重连中

长时间运行的操作绝不得冻结界面。

---

## 原则 4

视觉反馈应始终存在。

每个用户操作都应收到即时反馈。

示例：

正在连接...

正在上传...

正在认证...

HostKey 验证中...

传输进度...

用户绝不应怀疑应用程序是否仍在工作。

---

# 布局

应用程序采用三面板布局。

```
+-------------------------------------------------------------+
| Toolbar                                                     |
+-------------+----------------------------+------------------+
|             |                            |                  |
|             |                            |                  |
| Session     |        Terminal            |      SFTP        |
| Tree        |                            |                  |
|             |                            |                  |
|             |                            |                  |
+-------------+----------------------------+------------------+
| Status Bar                                                  |
+-------------------------------------------------------------+
```

布局应保持简洁、无干扰。

---

# 会话树

会话树是主要的导航组件。

职责：

- 主机分组
- 收藏
- 最近连接
- 搜索
- 上下文菜单

树应支持：

- 展开
- 折叠
- 拖拽
- 重命名
- 键盘导航

---

# 终端视图

终端是主要的工作区。

职责：

- 终端渲染
- 剪贴板
- 选择
- 调整大小
- 键盘输入

渲染委托给 xterm.js。

Core 持有终端状态。

---

# SFTP 视图

SFTP 面板提供图形化文件管理。

推荐布局：

```
本地文件

← 拖拽 →

远程文件
```

功能：

- 上传
- 下载
- 重命名
- 删除
- 创建目录
- 刷新

未来功能：

- 多选
- 后台队列
- 同步

---

# 对话框

对话框应仅在必要时打断用户。

示例：

- 未知 HostKey
- HostKey 已变更
- 删除确认
- 需要凭据

进度对话框应尽可能为非阻塞的。

---

# 通知

通知应当是轻量级的。

示例：

已连接

上传完成

主机已保存

配置已更新

错误应提供可操作的信息。

---

# 搜索

搜索应全局可用。

未来的快捷键：

Ctrl + K

搜索应能够定位：

- 主机
- 分组
- 收藏

搜索绝不应要求手动展开树。

---

# 键盘导航

键盘使用是一等交互模式。

常用操作应有快捷键。

示例：

Ctrl + N

新建主机

Ctrl + F

搜索

Ctrl + W

关闭会话

未来的快捷键应保持一致。

---

# 多会话

UI 应支持同时打开多个会话。

每个会话应保持隔离。

切换会话绝不应自动重连。

---

# 进度显示

长时间运行的任务应暴露进度。

示例：

连接

认证

上传

下载

目录加载

进度应始终由 CoreEvent 驱动。

---

# 主题

应用程序应支持：

- 浅色主题
- 深色主题

主题选择完全属于 UI。

Core 不知晓主题的存在。

---

# 窗口状态

UI 持有：

- 窗口尺寸
- 窗口位置
- 面板尺寸
- 分割条位置
- 活跃标签页
- 当前焦点

Core 绝不得访问这些状态。

---

# 可访问性

界面应通过以下方式保持可用：

- 键盘
- 高 DPI 显示器
- 屏幕缩放

视觉清晰度优先于装饰效果。

---

# 性能目标

界面应优先考虑响应性。

推荐目标：

- 快速启动
- 平滑滚动
- 即时输入响应
- 低内存占用
- 稳定的帧率

动画绝不应降低可用性。

---

# 未来的扩展

UI 应支持未来的模块，而无需重新设计架构。

可能的补充：

- 端口转发
- SSH Agent
- 后台传输
- 插件面板

新功能应自然地集成到现有布局中。

---

# 总结

UI 是一个呈现层。

其职责仅限于：

- 渲染
- 交互
- 反馈

业务逻辑属于 Core。

UI 通过 CoreEvent 反映运行时状态。

清晰的界面应在不增加复杂性的前提下提升生产力。
