# 产品交互

> 定义应用程序的交互理念与工作流。

本文档规定用户如何与应用程序进行交互。

它侧重于交互一致性，而非视觉外观。

本文档**不**旨在定义 UI 实现细节。

---

# 当前开发状态

项目当前优先关注：

1. 架构
2. Core 运行时
3. 业务逻辑
4. 性能
5. 稳定性

在早期开发阶段，用户界面的实现有意保持简化。

交互优化将在 Core 达到功能完备后成为主要焦点。

---

# 设计理念

应用程序应当让人感觉：

- 可预测的
- 响应式的
- 高效的
- 熟悉的

界面应最小化不必要的用户操作。

每个交互都应有明确的目的。

---

# 核心交互原则

## 原则 1

一次操作。

一个结果。

每个用户操作应恰好产生一个预期的结果。

不应出现意外行为。

---

## 原则 2

界面绝不应阻塞。

长时间运行的操作必须异步执行。

UI 在以下期间保持可用：

- 连接中
- 上传中
- 下载中
- 刷新目录中
- 加载会话中

---

## 原则 3

状态应始终可见。

用户应立刻理解：

- 正在发生什么
- 什么已完成
- 什么失败了
- 什么需要用户输入

界面绝不应出现冻结的现象。

---

## 原则 4

破坏性操作需要确认。

示例：

- 删除主机
- 删除远程文件
- 删除本地文件
- 覆盖已有文件

确认应仅在必要时出现。

---

# 启动体验

启动流程应当是轻量级的。

推荐的流程：

```
启动

↓

加载配置

↓

加载主机

↓

恢复 UI 状态

↓

就绪
```

应用程序应尽可能早地变为可交互状态。

---

# 主机管理

主机是主要的入口点。

常用操作：

- 创建
- 编辑
- 删除
- 复制
- 收藏
- 移动分组

主机应始终保持可用，无论连接状态如何。

---

# 连接工作流

典型工作流：

```
双击主机

↓

会话已创建

↓

正在连接

↓

认证

↓

Shell 就绪
```

连接进度应始终可见。

---

# HostKey 工作流

未知主机：

```
连接

↓

未知 HostKey

↓

显示指纹

↓

信任

↓

继续
```

HostKey 已变更：

```
连接

↓

HostKey 已变更

↓

显示旧指纹

↓

显示新指纹

↓

用户决定

↓

继续 / 中止
```

用户应始终理解连接为何被中断。

---

# 认证工作流

认证应需要最少的交互。

推荐的优先级：

```
SSH Agent（未来）

↓

私钥

↓

密码
```

凭据提示应仅在必要时出现。

---

# 终端工作流

打开会话后应立即显示终端。

终端是主要的工作区。

常用操作：

- 输入
- 复制
- 粘贴
- 调整大小
- 搜索（未来）

终端绝不应意外失去焦点。

---

# SFTP 工作流

图形化文件管理器是终端的补充。

典型工作流：

```
浏览

↓

拖拽

↓

传输

↓

进度

↓

完成
```

传输过程绝不应打断浏览。

---

# 文件传输

传输操作应始终暴露：

- 进度
- 速度
- 剩余时间
- 结果

失败应清晰说明：

- 什么失败了
- 为什么会失败
- 是否可以重试

---

# 多会话

每个会话独立运行。

更改一个会话绝不得影响其他会话。

关闭一个会话绝不应断开其他会话。

---

# 会话恢复

未来版本可能支持会话恢复。

预期的工作流：

```
意外断开

↓

重新连接

↓

恢复终端

↓

继续工作
```

恢复应尽可能自动化。

---

# 搜索

搜索应能够定位：

- 主机
- 分组
- 收藏

搜索不应要求手动展开树。

未来版本可能支持模糊匹配。

---

# 键盘交互

常用操作应可通过键盘完成。

示例：

```
Enter

连接

Delete

删除主机

F2

重命名

Ctrl + F

搜索

Ctrl + W

关闭会话
```

鼠标交互绝不应是唯一的操作方式。

---

# 上下文菜单

上下文菜单应仅包含与所选对象相关的操作。

示例：

主机：

- 连接
- 编辑
- 复制
- 删除

远程文件：

- 下载
- 重命名
- 删除

避免包含无关操作的通用菜单。

---

# 错误呈现

错误应说明：

- 发生了什么
- 为什么会发生
- 用户接下来可以做什么

示例：

不应是：

```
Connection Failed
```

而应是：

```
认证失败。

请验证您的用户名、密码或私钥。
```

可操作的信息优先于技术细节。

---

# 通知策略

通知应当是轻量级的。

示例：

- 已连接
- 上传完成
- 下载完成
- 主机已保存

长时间运行的操作应使用进度指示器，而非重复的通知。

---

# 一致性

相似的操作在整个应用程序中应表现一致。

示例：

双击始终打开。

删除始终要求确认。

重命名始终使用相同的交互方式。

一致性比新颖性更重要。

---

# 未来的改进

以下内容有意推迟到 Core 开发完成之后：

- 高级动画
- UI 打磨
- 主题自定义
- 布局优化
- 丰富的拖放效果
- 可访问性增强
- 细粒度的交互改进

这些改进不应要求更改 Core 架构。

---

# 总结

交互模型遵循一个简单的原则：

```
用户操作

↓

Core 请求

↓

Core 事件

↓

UI 反馈
```

用户应始终理解：

- 他们请求了什么。
- 应用程序正在做什么。
- 最终结果是什么。

交互质量应在不增加复杂性的前提下提升生产力。
